# CPLayout Agent Known Gaps

This file tracks gaps in the agent/skill process layer. It does not replace product validation checklists.

| Gap | Impact | Current mitigation |
| --- | --- | --- |
| Dynamic reasoning routing is documented and tested, but runtime model settings remain session-selected. | `AGENTS.md`, route data, skills, and custom agents no longer pin a repo-wide xhigh default; the prompt hook can advise a complexity band and reasoning effort. It cannot change an already-running session's model settings by itself. | Start each non-trivial pass with an explicit complexity analysis and selected reasoning effort; use `xhigh` only when warranted by native/runtime proof, architecture, storage, managed policy, release gates, Google Earth proof, or broad cross-module risk. |
| Custom agent runtime spawning was exercised in the 2026-06-02 plan-consolidation pass, but fresh-session hook-injected routing remains unverified after merge. | Subagents returned useful read-only findings in this session, but automatic route-to-agent behavior depends on the active runtime, trusted project config, and available multi-agent tools. | Keep agents read-only by default; in the next fresh session verify prompt-triage context and record either spawned specialists or `Accepted fallback:`. |
| Persistent subagent authorization is now documented, but local hooks cannot guarantee execution by themselves. | The owner preference is durable in `AGENTS.md`, skill references, and prompt registry, yet a coordinator could still ignore advisory context in an unmanaged session. | Use managed `requirements.toml`, managed hooks, and reviewer discipline for stronger process adherence; continue to require explicit subagent decision summaries. |
| Hook scripts are validated directly, but true in-session injection still requires a fresh Codex session after merge. | The `UserPromptSubmit`, `SubagentStart`, and `PreToolUse` scripts return valid sample output where expected, while the disabled Stop compatibility script must return no output. Active injection depends on trusted project config and runtime hook loading. | Start a fresh Codex session on the merged branch and prompt `Use Google Earth imagery and SQLite to improve center pivot UI`; verify injected context mentions only the top ranked specialists and CPLayout boundaries, and verify no Stop continuation prompt appears. |
| Managed hook enforcement is documented but not endpoint-verified here. | The example `requirements.toml` can parse locally, but non-bypass behavior depends on managed requirements deployment, copied scripts under the managed directory, Codex restart, and `/hooks` verification on the target machine. | Use `docs/codex-managed-hook-deployment.md`; after deployment, verify startup config, managed hook trust status, and sample prompts in a fresh Codex session. |
| Managed prompt triage depends on route data availability when scripts run outside the repo. | A managed script copied to an administrator directory can find route data from the current CPLayout checkout or adjacent managed files, but neither path is endpoint-proven. | Copy `.codex/hooks/cplayout_route_data.json` with managed scripts or run Codex from the CPLayout checkout; verify a matched prompt emits expected route ids. |
| Hook guardrails are not full command enforcement. | Local `PreToolUse` can deny narrow destructive commands, but broader policy still depends on model behavior and managed deployment. | Use managed requirements `[rules].prefix_rules` for hard command prompt/forbid policy if stronger enforcement is required. |
| Stop-hook continuation behavior is disabled. | Current official docs expose Stop continuation, but CPLayout observed repeated continuation prompts from stale or ambiguous thread context. `.codex/hooks.json` no longer registers Stop, and `cplayout_stop_multi_agent.py` is a silent compatibility no-op. | Keep missing subagent accounting visible through `AGENTS.md` and `UserPromptSubmit` context only; do not re-enable Stop continuation without a fresh-session payload audit and loop-proof tests. |
| Prompt triage is weighted keyword scoring. | Broad or unusual prompts may miss a relevant specialist or rank specialists imperfectly. | Route data caps output at 3 specialists and keeps broad terms low weight; the coordinator still owns final routing using `AGENTS.md`, repo evidence, and source-backed judgment. |
| Google Earth-inspired help prompts can be under- or over-routed if phrasing drifts. | Phrases such as companion evidence, map imagery organization, import wizard, and onboarding help need imagery, interface, and curator review, while broad `help` alone should not trigger CPLayout specialists. | Keep phrase-specific route data and tests current; avoid adding broad standalone `help` or `process` weights that would over-route unrelated prompts. |
| Source ledger is a seed, not a complete research knowledge base. | Center-pivot design, UI, database, and imagery methods still need task-specific source review. | Require source-backed updates for each new claim and keep unknowns explicit. |
| The Imagery/ML capability roadmap is active, but most phases are future proof gates rather than shipped behavior. | `docs/imagery-ml-capability-roadmap.md` sequences multi-year work, but it does not by itself create app import, storage, native ML, native imagery, field-trial, or production-readiness claims. | Treat the roadmap as an executive plan; promote a phase only after its listed validation gates, source checks, and proof artifacts pass. |
| `cplayout-imagery-evidence-v2` now has a strict core validator, Python emitter, and standalone verifier, but it is still not a project or app-import schema. | `packages/core/src/imageryEvidence.ts` can classify strict v2 companion packets as `blocked` or `ready_for_read_only_report` and candidate rows as `metadata_only`, `blocked`, or `calibrated_projected_xy`; `build-evidence-packet` now emits the v2 packet shape with local-only flags, visual metrics when a readable local image is supplied, attribution, calibration metadata, and projected truth gating; `npm run verify:imagery-evidence` can validate a packet locally and optionally require a calibrated projected candidate. Teams could still mistake that for permission to persist raw imagery/CV/model evidence in `PivotProject`, project ZIPs, native SQLite, KML/KMZ exports, or browser project storage. | Keep the packet companion-owned with `canonicalGeometryMutation: false`, `evidenceOnly: true`, `appImportable: false`, and `writesProjectDatabase: false`; use the emitter and verifier for read-only review gates only until a separate Phase 4 reducer-confirmed projected-XY draft workflow is implemented and tested. |
| Local design-guide summaries are advisory records, not project data. | The six local Valley design-guide PDFs now have page counts and curated page/line-backed topic summaries in `docs/design-guides/`, but the PDFs, extracted text, manifests, and tool reports remain local research artifacts. They must not become `PivotProject`, native SQLite, web local-storage, ZIP archive, KML/KMZ, or automatic projected-XY geometry data. | Keep raw artifacts under ignored `reports/design-guides/`, commit only curated summaries with source hashes and page/line references, and require `npm run validate:design-guides` when these records change. |
| Advisory corner-arm config and envelopes do not prove proprietary kinematics. | Public manufacturer pages and local PDFs can guide metadata and review surfaces, but CPLayout does not yet model manufacturer-specific steering, sequencing, or sprinkler timing accurately enough to merge corner-arm coverage into layout feasibility. | Store `machine.cornerArm` as optional advisory data only, keep `evaluateAdvisoryCornerArm` separate from `evaluateLayout`, and require qualified review plus source-backed tests before treating corner-arm coverage as allowed coverage. |
| Center-pivot awareness features are not certified automated design. | CPLayout can now preserve planning boundaries, machine zones, linear move paths, measurement lines, pump/well locations, underground pipe/wire paths, power poles/lines, existing pivot evidence, minimum-clearance gates, operator-supplied local cost-input status, transient machine-zone candidate reviews, multi-zone scenario compilation, generated within-field multi-pivot advisory screening, SVG/MapLibre generated-plan overlay display, explicit save-to-machine-zone review features, local advisory design report preview/export with current/missing/stale generated review-zone audit, full-scope compiled-boundary geometry and coverage/dry-acre metrics, projected-XY collision/review zone evidence with severity flags, advisory current/full-circle machine strategy comparison, path-based advisory linear/lateral swept-strip scoring, operator-labeled bender/second-pivot opportunity envelopes, and advisory obstacle interaction summaries for hard-blocking, no-spray, span-clearance, tower-track, utility-path, outside-reach, operator/source crossing-profile, blocked-profile, and clearance-shortfall evidence. That does not prove first-class saved multi-pivot machines, runtime multi-pivot collision avoidance, proprietary bender tower-pivot kinematics, certified obstacle crossing/passability, certified linear/lateral design, vendor cost quotes, certified/final client deliverables, or the Will Rhea / Jason Harmelink final layout. | Keep these features advisory and projected-XY only. Require explicit operator apply actions, local cost inputs, qualified field/vendor review, and future focused tests before promoting first-class multi-pivot project schemas, runtime collision prevention, proprietary bender mechanics, certified crossing/passability, certified linear/lateral design, vendor quote workflows, or certified/final client deliverables beyond local advisory report exports. |
| The local Will Rhea / Jason Harmelink KMZ now has an ignored advisory report path, but the current local run is blocker evidence. | `tools/generateClientKmzAdvisoryReport.ts` reads the local ignored KMZ, hashes it, imports the full-scope boundary, machine zones, LRDU measurement line, and pivot evidence into an ephemeral projected-XY analysis project, and writes local ignored report files with `canonicalGeometryMutation: false`, `writesProjectStorage: false`, `googleEarthRenderProof: false`, and `finalClientDesign: false`. | Process records can lag product code after implementation passes. | Earlier process-only updates did not change runtime code, but later passes may add storage, UI, or companion behavior that needs record updates. | Keep this file, the focused plan, and source ledger synchronized after product changes; do not use older process-only statements as current product status. |
| No first-class ML/CV pivot-center locator loop existed before the 2026-06-01 loop document. | Existing browser mapping loop and boundary-focused ML reports cannot prove automatic center-pivot locating quality. | Use `docs/ml-cv-pivot-locating-improvement-loop.md` and `npm run verify:ml-cv-loop` as the pivot-locator control loop until executed evidence rows replace planned rows. |
